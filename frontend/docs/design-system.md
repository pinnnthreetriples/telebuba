# Дизайн-система Telebuba: как она устроена

Этот документ — про решения. Значения печатает
[`design-system.html`](./design-system.html) из самих токенов, компоненты показывает живой
каталог (`npm run catalog`), а здесь лежит то, чего ни один генератор вывести не может:
почему ступеней столько, что во что слито и что оставлено раздельно.

Прозы в `tailwind.config.ts` больше нет умышленно. Она там была — 350 строк из 731, — и
файл, в котором обоснование занимает половину, читается хуже, чем два файла.

## Три уровня и один источник

```
src/shared/design-system/
├── tokens/
│   ├── primitives.ts   ← настоящие значения: палитра, радиусы, тени, слои, шрифты
│   ├── semantic.ts     ← назначение краски; ни одного значения, только ссылки
│   ├── typography.ts   ← ступени размера, роли, интерлиньяж, межбуквенное
│   ├── spacing.ts      ← ритм + шкалы размеров (size/width/height/min/max)
│   ├── motion.ts       ← длительности и кривые
│   ├── names.ts        ← состав шкал списком, для тех, кому не нужны значения
│   └── index.ts
└── index.ts            ← публичный API сегмента
```

Уровень 1 хранит значение один раз. Уровень 2 объясняет назначение и ссылается на
уровень 1. Плоские имена, которые набирает класс, — проекция уровня 2, и таблица
соответствий лежит в шапке `semantic.ts`.

### Семантика названа в самом классе, а не только в структуре

Первая версия этих файлов держала структуру назначений и оставляла классы прежними:
`bg-white`, `text-white`, `bg-primary`, `text-ink`. Это не работало, и не по стилю, а по
существу: белый цвет карточки и белый цвет надписи на залитой кнопке были **одним**
классом, поэтому перекрасить одно, не перекрасив другое, было нельзя. Синий одновременно
был заливкой действия, краской ссылки и тёмным синим, читаемым на тоне. Семантический
уровень, который нельзя применить, — это комментарий, а не уровень.

| Роль                                  | Класс                              | Было                                   |
| ------------------------------------- | ---------------------------------- | -------------------------------------- |
| белая поверхность                     | `bg-surface-card`                  | `bg-white`                             |
| чернила на залитом действии           | `text-on-action`                   | `text-white`                           |
| одна строка на тёмной поверхности     | `text-on-inverse`                  | `text-white`                           |
| основные чернила                      | `text-content-primary`             | `text-ink`                             |
| и `-secondary` / `-muted` / `-subtle` |                                    | `text-ink-body` / `-muted` / `-subtle` |
| заливка действия                      | `bg-action-primary`                | `bg-primary`                           |
| наведение на незалитый контрол        | `bg-action-hover`                  | `hover:bg-primary-tint`                |
| нажатие залитой кнопки                | `bg-action-pressed`                | `bg-primary-press`                     |
| тон смысла «в работе»                 | `bg-info-tint`, `text-info-strong` | `bg-primary-tint`, `text-primary-deep` |

**Что не переименовано:** `canvas`, `line`, `term`, `success`, `warning`, `danger` уже
были ролями — они называют назначение, и второго смысла ни один не несёт. Переименование
стоило бы 400 правок и не добавило бы ни одной новой независимости. Работа была не в
приставках, а в трёх краcках, делавших по две работы разом.

`white` и `black` остались, но только под альфой над фотографией — там это край диапазона,
а не роль, и плоского композита для них нет. Голые `bg-white`/`text-white` банит линтер.

Проверка: переименование меняет **имена, не значения**, поэтому все 22 снимка обязаны
остаться байт-идентичными — и остались. Для правки в 700 мест это самое сильное
доказательство, какое можно получить. Заодно она вскрыла ассертацию, проходившую по
случайному совпадению подстроки (`toContain('text-primary')` совпадало с
`text-primary-deep`), и добавила гейту контраста пару, которую раньше нельзя было
измерить: `on-action on action-primary` было неотличимо от белой карточки.

### Почему уровнем ниже Tailwind, а не в конфиге

Потребителей у значений пять, и один из них конфиг импортировать не может:

| Потребитель                                               | Что берёт            | Как              |
| --------------------------------------------------------- | -------------------- | ---------------- |
| `tailwind.config.ts`                                      | все шкалы            | импорт           |
| `src/shared/lib/cn.ts`                                    | состав шкал          | импорт           |
| `scripts/dead-tokens.mjs`                                 | состав шкал          | `loadTokens.mjs` |
| `scripts/design-system-doc.mjs`                           | значения             | `loadTokens.mjs` |
| `eslint-rules/design-tokens.js`                           | состав шкал          | `loadTokens.mjs` |
| `contrast.test.ts`, `motion.test.ts`, `typeRoles.test.ts` | скомпилированный CSS | импорт конфига   |

`cn.ts` — код приложения, а конфиг тянет `tailwindcss/plugin`: импорт затащил бы плагин
Tailwind в браузерный бандл. Поэтому значения лежат ниже конфига, а не в нём.

### Что это починило

Копий состава шкал было **шесть**, и каждая расходилась по-своему:

| Где                             | Что держала                                                 | Как ломалась                                                                                             |
| ------------------------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `tailwind.config.ts`            | значения                                                    | — (источник)                                                                                             |
| `cn.ts`                         | 12 ступеней ритма, 8 рунгов, 12 ролей, радиусы, интерлиньяж | tailwind-merge не знает ступень → не разрешает конфликт → **перекрытие вызывающего молча выбрасывается** |
| `eslint-rules/design-tokens.js` | `TOKEN`, `TYPE_RUNG`                                        | новый цвет не прикрыт правилом; гейт зеленеет, перестав смотреть                                         |
| `scripts/dead-tokens.mjs`       | разбор по отступу                                           | перенос блока на два пробела ломает гейт                                                                 |
| `scripts/design-system-doc.mjs` | разбор по отступу                                           | не умеет читать ссылку `background.canvas` — упал бы от появления семантики                              |
| `contrast.test.ts`              | `white: '#ffffff'` вручную                                  | палитра и то, что измеряет гейт, — два набора                                                            |

Опаснее всех был `cn.ts`: расхождение возникает не при переименовании (его заметили бы),
а при **добавлении** ступени, и ничего не красит неправильно — просто перестаёт работать.

Теперь состав вычисляется из самих шкал (`names.ts`), а `loadTokens.mjs` собирает токены
esbuild и отдаёт Node настоящие объекты. Разбор текстом удалён целиком.

## Закрытые шкалы

Каждая шкала стоит в **корне** `theme`, а не в `extend`. Это не стиль: `extend`
оставляет шкалу Tailwind доступной рядом со своей.

Палитра была последней в `extend`, поэтому `bg-blue-500` компилировался и красил синий,
которого никто не выбирал. Между двумя палитрами стояла одна регулярка в правиле ESLint —
читающая только `src` и только вне тестов. **Закрытый набор, который держит grep, — не
закрытый набор.** Теперь класс чужой палитры не выпускает правила вовсе, а сообщение
правила объясняет молчащий класс, а не предотвращает его.

Замена палитры означает, что четыре ключевых слова Tailwind приходят вместе с ней:
`transparent` и `current` — отказ красить и ссылка на собственные чернила;
`white`/`black` — два конца, которых тёплая палитра не заменяет. `black` встречается
только под альфой над фотографией. `inherit` намеренно отсутствует: носителя у него нет,
и гейт мёртвых токенов прав, отказываясь от ступени без носителя.

## Ключ `DEFAULT` у движения

`transitionDuration` и `transitionTimingFunction` в корне `theme` заменяют шкалы Tailwind
**вместе с их ключами `DEFAULT`**. Tailwind впекает эти два умолчания в каждую утилиту
`transition-*`, поэтому замена без `DEFAULT` выпускает `.transition-colors` со свойством
и без длительности, а начальная длительность в CSS — `0s`.

Коммит, сделавший токены авторитетными, выключил 25 переходов приложения. Шесть гейтов
были зелёными над ним сутки: не идущий переход — не сырое значение, не провал контраста и
не расхождение с документом. `motion.test.ts` компилирует конфиг и проверяет, что
длительность выходит, — единственная форма проверки, которая это ловит.

**Эти два ключа удалять нельзя.** Они выглядят дублированием `state` и `out` и им не
являются.

### Слито этой правкой

| Было                                    | Стало                           | Почему                                        |
| --------------------------------------- | ------------------------------- | --------------------------------------------- |
| `micro` 10.5 + `tiny` 11                | `tiny` 12                       | полпикселя — не ступень                       |
| `body` 12.5 + `lead` 13                 | `body` 14                       | то же, и основной текст должен читаться       |
| роль `meta` + роль `caption`            | `caption`                       | после слияния ступеней рисовались одинаково   |

**Оставлено раздельно:**

| Пара                                                 | Почему не слито                                                                                                          |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `primary-press` (#0057db) и `primary-deep` (#0052cc) | разные роли и разные значения: нажатие залитой кнопки против текста на `primary-tint` (4.38:1 → 6.18:1)                  |
| `duration.DEFAULT` и `duration.state`                | см. раздел про `DEFAULT` — удаление выключает 25 переходов                                                               |
| `easing.DEFAULT` и `easing.out`                      | то же                                                                                                                    |
| `border.focus` и `action.primary`                    | один синий, два решения: перекрасить действие, не перекрасив фокус, должно быть возможно                                 |
| `content.disabled` и `content.subtle`                | недоступный контрол и мелкая подпись меняются по разным поводам                                                          |
| `scrim` (55%) и `veil` (40%)                         | завеса над одной фотографией против завесы над страницей: на первой пишут белым и берут 4.5:1, на второй не пишут ничего |
| `Button` и `IconButton`                              | разные контракты доступности: у иконочной кнопки имя приходит из `aria-label`, а не из содержимого                       |
| `docs/design-system.html` и живой каталог            | первый печатает значения из токенов, второй рендерит настоящие компоненты; ни один не может заменить другой              |

## Гейты

| Команда                                 | Что держит                                                                                          |
| --------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `npm run lint`                          | сырое значение мимо шкалы — ошибка (правило `design-tokens/no-raw-values`)                          |
| `npm run ds:dead`                       | ступень без единого носителя — ошибка                                                               |
| `npm run ds:doc:check`                  | документ значений разошёлся с токенами — ошибка                                                     |
| `npm test` → `contrast.test.ts`         | WCAG AA (4.5:1 для текста, 3:1 для графики) на каждой паре краска/подложка                          |
| `npm test` → `motion.test.ts`           | утилиты `transition-*` выпускаются с длительностью и кривой                                         |
| `npm test` → `index.test.ts`            | одеяло `prefers-reduced-motion` перекрывает каждое сокращение в файле; литеральных кривых в CSS нет |
| `npm test` → `typeRoles.test.ts`        | каждая роль выпускается в слой `components` и разрешает свою краску                                 |
| `npm test` → `axe` в тестах компонентов | доступность примитивов, фокус с клавиатуры                                                          |
| `npm run visual`                        | снимки каталога: 12 проверок, 2 ширины (1280 и 375)                                                 |
| `npm test` → `index.test.ts`            | всё, чем `index.css` красит, приходит из палитры; десять обходов гейта падают в самом гейте         |
| `npm test` → `classMerge.test.ts`       | ни один примитив `shared/ui` не склеивает класс вызывающего строкой                                 |
| `npm test` → `tokens.test.ts`           | каждая семантическая роль доходит до класса; ни один класс не обходит роль к примитиву              |
| `npm run typecheck`, `npm run build`    | типы и продуктовая сборка                                                                           |

Эталоны снимков разделены по платформе: `e2e/__screenshots__/linux/` — авторитетный
набор, на нём стоит CI и он блокирует merge; `e2e/__screenshots__/win32/` — локальное
удобство. Растеризация шрифта у платформ разная, и разная не на глаз: одна и та же
кнопка мерит 126px на Windows и 125px на Linux при одном и том же файле Inter. Поднять
порог до пропуска этого сдвига значит перестать видеть сдвиг ступени токена — то есть
ровно то, зачем гейт есть.

После умышленного изменения внешности обновляются оба набора: локальный —
`npm run visual:update`, линуксовый — прогоном CI, который на первом падении выкладывает
сгенерированные эталоны артефактом `design-system-screenshots`.

Правило `no-raw-values` целиком выключено внутри `tokens/` — это не дыра: его
утверждение «значение принадлежит системе, а не месту вызова», и эти файлы **и есть**
система. Выключение ограничено `tokens/`, а не `design-system/`: рецепт по соседству
писать hex по-прежнему не может.

`Input.test.tsx` это проверяет сравнением, а не числом.

## Краска с альфой в кейфрейме

Восемь объявлений `box-shadow` внутри `@keyframes` носили краску литералом —
`rgba(0, 102, 255, 0.3)`. Это была вторая запись значения, которое палитра уже хранит:
перекрасив `blue600`, кольцо пульса осталось бы прежнего цвета. Нашло ревью, а не гейт, и
причина поучительна — прежняя проверка искала `cubic-bezier`, то есть ровно то, что
однажды сломалось, а не КЛАСС «литерал вместо токена».

Решение — канальная форма, **вычисляемая** из палитры, поэтому второй копии значения не
появляется:

```css
box-shadow: 0 0 0 0 rgb(theme('channel.action') / 0.3);
```

`channel.action` — это `channelsOf(palette.blue600)` → `0 102 255`. Пробельная запись
`rgb()` — обычный CSS, без относительного цветового синтаксиса, поддержанного не везде.
Сама альфа остаётся в кадре, и это не недоделка: 0.3 и 0.9 — форма **анимации**, ровно как
7px разлёта рядом, а не краска. Токен отвечает на «какого цвета», кадр — на «как движется».

Заодно `#5ba3ff` (свечение загружающейся строки) получил имя `blue400` — он не имел его
вовсе и жил только внутри кадра.

### Гейт: закрыт список красок, а не список свойств

Гейт под это переписан дважды, и обе прошлые версии ошибались одинаково — брали открытый
список за закрытый:

1. Первая банила **форматы** (`#hex`, `rgb()`/`hsl()` с числом в первом аргументе) и
   потому пропускала `transparent`, `red`, `oklch()`, `color()`, `currentColor`, `Canvas`.
2. Вторая перечисляла **свойства**, способные нести краску, — и её провели насквозь:
   `background-image: linear-gradient(red, blue)` и `filter: drop-shadow(red 0 0)` в
   список не входили. Заодно любой `theme()` считался краской, поэтому
   `color: theme('spacing.md')` проходил как токен.

Закрытый список тут ровно один, и он на другой стороне. Перечислить **краски** можно:
имена CSS Color 4 не пополнялись с 2014 года. Перечислить **свойства**, которые их несут,
нельзя. Поэтому свойства не перечисляются вовсе: сканируется значение каждого объявления,
и вопрос к атому не «законен ли он здесь», а «краска ли это».

| Правило                                                                                                                               | Что закрывает                                                                   |
| ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| **(A)** ни в одном объявлении нет атома-краски: hex, имя функции цвета, имя CSS Color 4, системное имя, `transparent`, `currentColor` | `linear-gradient(red, blue)`, `drop-shadow(red 0 0)` — свойство не спрашивается |
| **(B)** свойство только-краски (`color`, `*-color`, `fill`, `stroke`) не содержит ничего, кроме вызовов `theme('colors.…')`           | `color: theme('spacing.md')` — непалитровый токен оставляет остаток             |
| **(C)** hex не встречается в файле вообще, включая комментарии                                                                        | вторую запись значения в прозе рядом с кодом                                    |

Разбор идёт plain PostCSS по **исходнику**, а не по скомпилированному листу: там каждый
`theme()` уже развёрнут в литерал, и отличить токен от краски нечем. Что путь внутри
`theme()` существует, доказывает не гейт, а компиляция: она падает на неизвестном ключе.

**Чего гейт не делает.** На составных свойствах (`background`, `border`, `box-shadow`) он
не спрашивает, из какой шкалы токен: длина там законна по позиции — `box-shadow` берёт из
`spacing` смещение, — и правило «только палитра» дало бы ложное срабатывание. Токен не той
шкалы даёт там невалидный CSS, который не красит ничего; молча покрасить не тем цветом он
не может. Открытым остаётся и список имён функций: функция цвета, которой в CSS ещё нет,
пройдёт правило (A), если её имени нет в списке, — но не пройдёт (B) на свойстве
только-краски.

Отрицательные случаи лежат в самом гейте, `test.each` на десять строк: три обхода,
найденных ревью, плюс семь, которые прошлая версия банила перечислением форматов. Гейт, у
которого отрицательных случаев нет в CI, — это гейт, про который неизвестно, смотрит ли он
ещё.

## Второй проход: семь мест, где система была на словах

Первый проход построил уровни. Ревью нашло семь мест, где уровень объявлен и не применим,
или применим двумя способами. Общая форма у всех семи одна: **правило, которое ничего не
держит, выглядит как правило.**

### 1. Фокус получил собственную роль

`border.focus` был ступенью с самого начала и не доходил ни до одного класса: восемь
контролов рисовали фокус через `outline-action-primary`. То есть перекрасить кнопки
означало перекрасить каждый индикатор фокуса — ровно та связь, которую отдельная ступень
должна разрывать.

|          |                                                 |
| -------- | ----------------------------------------------- |
| классы   | `outline-focus`, `border-focus`, `shadow-focus` |
| значение | одно (`blue600`), имён два, копии значения нет  |
| гейт     | ESLint банит краску ДЕЙСТВИЯ в позиции фокуса   |

`shadow.focus` попал сюда же и был хуже общего токена: он носил `rgba(0,102,255,0.12)` —
копию синего действия внутри слоя токенов, куда гейт таблицы стилей не смотрит. Теперь
`rgb(${channel.focus} / 0.12)`.

Из всех дефектов, которые ловит правило ESLint, этот единственный **ничего не портит на
экране**. Поэтому ему нужен гейт, а не ревью: класс работает и выглядит правильным — до
дня, когда кнопки перекрасят.

### 2. Сборка классов — через `cn`

Пять примитивов склеивали класс вызывающего строкой: `IconButton`, `Modal` (два места),
`DataTable` (собственный `join`), `CollapsibleCard` (два места). Все под одним
объяснением: `cn` якобы затащил бы `shared/ui → shared/lib → баррель @tanstack`. Верно это
было только про **баррель**; `@/shared/lib/cn` — листовой модуль, и `Card` с `FormField`
импортировали его напрямую с самого начала.

Склейка — не уменьшенная версия слияния, а другой исход: в списке классов оказываются оба,
и побеждает тот, кого Tailwind выпустил ПОЗЖЕ, — порядок, который ничего не знает о том,
кто из двоих был перекрытием. Шапка таблицы годами полагалась на эту случайность:
`text-right` из `meta` побеждал базовый `text-left` потому, что Tailwind выпускает `right`
после `left`.

Гейт: ни один примитив `shared/ui` не интерполирует класс вызывающего в шаблонный литерал.
Ищется `${className}`; внутренний `${open ? 'rotate-180' : ''}` законен — терять там нечего.

### 3. Один источник брейкпоинтов

880 было записано дважды, 1024 — трижды (считая умолчание `lg` у Tailwind, которое
приложение носит 27 раз). Комментарий у `minWidth.table` это признавал вслух, что хуже, чем
не знать: признанное расхождение — решение оставить его.

`breakpoint` в токенах держит **числа**, а не строки: «таблица или карточки» решается в
JavaScript, на измеренной ширине контейнера, и строку с `px` пришлось бы разбирать назад.

| основа                 | куда идёт                             |
| ---------------------- | ------------------------------------- |
| `breakpoint.table` 880 | `min-w-table`, пол `useWideContainer` |
| `breakpoint.wide` 1024 | `lg:`, медиазапрос-подстраховка       |
| `breakpoint.card` 640  | `sm:`                                 |
| `breakpoint.split` 768 | `md:`                                 |

Шкала `screens` объявлена и закрыта тремя ступенями, которые приложение носит. `xl:`/`2xl:`
теперь не выпускают ни одного правила — та же тихая поломка, что была у палитры Tailwind, и
то же лечение: правило ESLint называет три существующие.

### 4. `Spinner`

Кольцо было собрано руками семнадцать раз, и копии разошлись — это и есть находка, а не
повторение строки:

| дорожка кольца                               | сайтов |
| -------------------------------------------- | ------ |
| `border-line border-t-action-primary`        | 7      |
| `border-line-strong border-t-action-primary` | 5      |

Дорожка была двумя серыми в одной работе. Стала одним — `line-strong`: на 2px дуги
волосяной серый на белом почти не читается, и кольцо превращается в одинокую синюю запятую.
Семь сайтов стали на шаг темнее — единственное намеренное изменение картинки.

Размеров было **семь**: локальный `Spinner` в `account-edit` брал размер числом, и вызовы
передавали 12, 13, 14 и 15 — четыре значения в пределах трёх пикселей, то есть не решение,
а место, где легла рука (тот же дефект, что `backdrop?: number` у диалога). Осталось три:
`sm` (в кнопке или строке), `md` (вместо блока), `lg` (вместо портрета). Тона —
`default`/`inverse`/`danger`.

`aria-hidden` — сохранение поведения, а не решение: все семнадцать колец были пустыми
`<span>` без роли. `role="status"` сделал бы хуже: кольца стоят внутри кнопок, которые
опрашивают сервер, и каждая живая область объявляла бы себя на каждом опросе.

Девять сочетаний лежат в каталоге, и должны были: кольцо рисуется только в момент ожидания,
поэтому ни на одном снимке страницы его нет.

### 5. Закрытые API компонентов

| было                         | стало            | почему                                                                                                                      |
| ---------------------------- | ---------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `<Modal className="w-form">` | `size="form"`    | через `className` приходила не только ширина: четыре сайта унесли из скопированной строки чужой `z={75}` и `w-[460px]`      |
| `<SurfHover shift={144}>`    | компонент меряет | оба вызывающих передавали неверное число: три кнопки `w-action` — это 138, а не 144, и раскрытие показывало 6px чужого фона |
| `<Card mb="mb-lg">`          | зазор у родителя | карточка ставила расстояние до того, что под ней, ничего об этом не зная; настройки просили `lg` четырежды и `xl` один раз  |

Ширина шторки (`w-[min(84vw,300px)]`) уехала в **вариант** `drawer-left`: шторка в
приложении одна, и её ширина принадлежит варианту, а не месту вызова. Пока она приходила
классом, `className` нельзя было убрать.

У `SurfHover` ширина пишется прямо в стиль узла, а не в состояние: через состояние
измерение вызывает второй рендер сразу после монтирования, поверхность носит
`will-change: transform`, её композитный слой переезжает, и текст на нём растеризуется
иначе. Визуальный гейт это увидел — 238 пикселей на экране нейрокомментинга, при сравнении
эталона с самим собой.

### 6. Семантический слой закрыт с двух концов

| дефект                                    | сколько | пример                                                                                            |
| ----------------------------------------- | ------- | ------------------------------------------------------------------------------------------------- |
| роль объявлена и не доходит до класса     | 8       | `content.disabled`, `feedback.info.base`, `action.disabled`                                       |
| класс объявлен и обходит роль к примитиву | 3       | `surface-card` брал `palette.white` напрямую — 143 сайта белой поверхности мимо уровня назначения |

Три из восьмерки (`info.base`, `info.pressed`, `danger.pressed`) стояли «для симметрии»
тонов, и шапка файла эту симметрию обещала вслух. Обещание оплачивалось мёртвыми
ступенями; теперь набор у тона такой, какие работы тон делает.

`warning.strong` стал `warning.press`: под именем `-strong` там стояло НАЖАТИЕ, тогда как у
«в работе» `-strong` — тёмная краска на тоне. Один суффикс, два смысла в соседних тонах.

Гейт читает **исходник**, а не значения, и это главное в нём: `content.disabled` и
`content.subtle` — один и тот же серый, поэтому сверка по значениям зачла бы мёртвую ступень
за живую. Роль — это путь, а не цвет.

### 7. Имена: тон, роль, интерлиньяж

`tone="primary"` у Badge и Notice стал `info`: тон обратной связи и цвет действия звались
одним словом, красясь разными ступенями. У `IconButton` тон `primary` остался — там это и
есть «главное действие».

`type-table-header` — роль, под которую в правиле ESLint год лежало письменное исключение:
«перенести эти два места на `type-eyebrow` нельзя, это изменило бы вид шапки в каждой
таблице, чтобы роль подошла». Верно; поэтому подошла роль. Отличается от `eyebrow` весом
(500 против 600) и снимает произвольное `tracking-[0.04em]` в обоих местах.

Интерлиньяж переехал **в роли**. У всех двенадцати он `body` — то самое значение, которое
они и рисовали, наследуя от `body`. Поэтому на экране не сдвинулось ничего, а роль
перестала зависеть от предка: `type-caption` внутри `leading-log` разъезжался на 1.85 и
выглядел не собой. Рунг РАЗМЕРА при этом остаётся голой строкой — на нём стоит `text-*`, и
вписать интерлиньяж туда значило бы переверстать сайты, которые взяли рунг, а не роль.

## Порог визуального гейта был слишком широк

`maxDiffPixelRatio: 0.002` стоял с комментарием, утверждавшим обратное: «0.2% заметно
меньше, чем любой сдвиг ступени токена». На снимке 1280×2000 это пять тысяч пикселей.

Принудительная перезапись (`--update-snapshots=all`) показала: отличались **двенадцать**
файлов, падали **два**. Под порогом прошли сдвиг раскрытой строки `SurfHover` на 48px,
полоса залипшей шапки поверх раздела и правки `Modal` с `IconButton`. Каждое «22 снимка не
изменились» в этой ветке означало «в пределах 0.2%», а не «побайтово».

Стало `maxDiffPixels: 40` — меньше площади одного глифа кегля 12px, и абсолютное, чтобы
большой снимок не получал большую поблажку. Возможным это делает разделение эталонов по
платформе: межплатформенная растеризация давала сотни пикселей, внутриплатформенная — единицы.

Одна страница не стояла на месте и при этом: нейрокомментинг расходился от прогона к
прогону на 238…500+ пикселей — **не** из-за этой ветки, тот же разброс воспроизводится на
коде из HEAD. В одиночном прогоне страница снимается побайтово одинаково шесть раз подряд, а
на четырёх воркерах промоушен композитного слоя гоняется с захватом. Поэтому снимочная
таблица стилей снимает `will-change` во время съёмки: это подсказка производительности и
ничего кроме, и без неё получается та же картинка, растеризованная одним способом.

## Что осталось сырым — и почему

| Значение                      | Где                              | Почему не токен                                                                                               |
| ----------------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `0.7s`…`2s` в `animation:`    | 13 объявлений `index.css`        | семь из них — бесконечные циклы; рунги под них — это семь токенов с одним носителем каждый                    |
| `5px` ножка стрелки подсказки | `.tb-tip-pop::before`            | геометрия треугольника, а не ритм                                                                             |
| `3px` сдвиг подсказки         | там же                           | путь, который проезжает элемент, а не расстояние между вещами                                                 |
| `!important` × 5              | одеяло `prefers-reduced-motion`  | должно перекрывать сокращения `animation:`/`transition:` из любого места файла; `index.test.ts` это проверяет |
| четыре hex-стопа градиента    | `ProfileModal`, `_profileShared` | декоративные, за не загрузившимся аватаром и превью; несут `eslint-disable` с причиной                        |

В `index.css` сырых красок не осталось ни одной — включая `transparent`, который раньше
стоял в двух объявлениях ключевым словом. Ключевое слово не «дрейфует», и правка не о
нём: исключение из правила «краска приходит только через `theme()`» — это ровно та щель,
в которую пролезает `red`. Гейт ниже поэтому не знает исключений.

`!important` на `.tb-time:focus-within` снят: `@layer base` закрывается в начале
`index.css`, поэтому правило **вне слоёв** и стоит после `@tailwind utilities` — оно
выигрывало и по специфичности (класс + псевдокласс против класса), и по порядку.
Перекрытие спорило в споре, который уже выиграло.
