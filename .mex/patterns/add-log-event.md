# Add or Rename a Log Event
1. Name it `<domain>_<what_happened>` — `warming_`, `neurocomment_`, `account_`, `telegram_`, `proxy_`, `tdata_`. There is ONE `logs` table; the per-domain feeds separate only by `event LIKE 'prefix%'`, so an unprefixed name is invisible in its own feed and leaks into every other.
2. Prefix by the domain that *reaches* the code, not the layer that emits it: a `core/` helper with a single service consumer takes that consumer's prefix (`core/telegram_client/_listener.py` → `neurocomment_listener_*`) and leaves a `ponytail:` marker naming the second-consumer ceiling.
   A `core/` helper with MANY domain consumers takes the prefix as a *parameter* instead of hard-coding one. The gateway does this: `execute(..., domain=)` runs every name it writes through `event_name` (`core/telegram_client/_util.py`), so warming's join is `warming_telegram_join_channel` and neurocomment's is `neurocomment_telegram_...`. The domain is bound once per domain at `services/<domain>/_seams.py` with `functools.partial`, never at a call site; `domain=None` (accounts / profile / channels — no per-domain feed) keeps the bare `telegram_*`. Pool events (`telegram_pool_*`) stay unprefixed: the pool is shared, not per-action. On the SPA side `eventLabel` strips the `<domain>_` before both lookups, so a prefixed code needs NO new i18n key.
3. Never reuse one name across two domains. `retention_purge_failed` was shared and contaminated both feeds in both directions; it is now `warming_` / `neurocomment_retention_purge_failed`.
4. Add the label to `logEvent` in **both** `frontend/src/shared/i18n/en.json` and `ru.json`, same key order, distinct text per domain — identical text defeats the split on the global Logs page. `tests/test_logevent_i18n_parity.py` only catches literal-level, literal-name call sites, so dynamic names need a manual check.
5. The colour is chosen TWICE and the name wins. `log_event`'s level maps to a status (`_STATUS_BY_LEVEL`: INFO→success/green, WARNING→amber, ERROR→red), but the neurocomment terminal runs the name through `frontend/src/shared/lib/log/eventSeverity.ts` first: a `_failed|_exhausted|_crashed|_dropped|_overloaded|_deleted|_banned` suffix is red whatever the level, a `_skipped|_gated|_cooled|...` one amber. So pick the level for the operator's *verdict* (a dead end they must act on is ERROR, not INFO — green reads as "noted, carry on"), and check the name's suffix does not overrule it by accident. Long-form explanations go in `logEventHint.<code>` in both locales; a drop event without one leaves the operator no way to learn what it cost.
6. `extra["reason"]` is the SPA's second vocabulary (`logEventReason`), rendered beside the label and shown RAW when unmapped. A bare ratio there (`"2/2"`) is already the daily rules' convention — re-join, channel pause, join request — so using it for anything else makes an unrelated event read as a burnt 48h budget (`neurocomment_generation_retry` did exactly that). Put the failing check's code in `reason` and the counters in fields of their own.
7. Filters (`event_prefix`) take a comma-separated prefix list; empty means all rows, an all-blank value means none. Escaping lives in `_event_prefix_clause` (`core/repositories/logs.py`) — never build a `LIKE` from operator input by hand.
8. Test the rename at the layer the caller uses, and assert the event name, not just the level.
9. Bound `extra`. `log_event` persists it as JSON, `GET /logs` serves it back as `LogEntry.extra` and `GET /events` streams it — so `extra` **is an HTTP response body**, and `str(exc)`/`repr(exc)`/`f"{exc}"` on a third-party exception publishes a proxy URL with `user:pass@host:port` or an absolute `.session` path (non-negotiable #12). Carry `type(exc).__name__` (the SPA reads `error_type`), stable codes, counts and ids; send the full text to the module's `logging.getLogger(__name__)`, which `core.logging.setup_logging` bridges into loguru's `debug.log` and leaves on the console — never a route. `tests/test_logevent_extra_bounds.py` fails on the known shapes; it is a drift guard, not a proof, so also check any *persisted* field the event's response model exposes (`WarmingAccountState.last_error`, `ProxyCheckResult.last_error`) — the gate reads only `extra`.

Verify: `rg -n '"<old_name>"'` across `.py`, `.ts(x)`, `.json`, `.md`, `.mex/`, `.github/` — comments and docstrings included. Editing an `api/v1` docstring changes the OpenAPI description, so re-run `uv run python -m tools.gen_api` or the CI drift gate fails. Views in effect: warming card `warming_,spam_status` + `account_id` (`WarmingBoard.tsx`), neurocomment feed `neurocomment` (`NeurocommentPage.tsx`), Logs page unfiltered. Do NOT add `spam_status` to the neurocomment feed — it is unprefixed and shared, so it would re-import warming's and the accounts page's probes.
