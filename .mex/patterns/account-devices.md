# Account Devices

1. An account has one or two sign-ins — desktop and/or mobile — each its own `.session` and its own fingerprint row; one session never presents two devices. Fingerprints are inserted once, never upserted.
2. The pool keys clients by account and device. A borrower naming no device gets the primary (desktop when the account has one); a named device the account lacks is refused with a stable code, never served by the other one. Standing subscriptions live on the primary and move with it.
3. Mobile connects with the Android app's own api credentials and `lang_pack="android"`; without them it is refused, never faked on the desktop credentials. Desktop is the default everywhere; mobile only by the operator's pick. A warming stint keeps the device it started on across restarts.
4. A second device signs in with the code the existing session reads from 777000, taken only from a message newer than the id read right before the request — never a host-clock cut-off. Phone and user id come from that session. Code requests are paced per account. A failure revokes and deletes the new session and stores nothing.
5. Logout/reset also end the second device and forget it; removal deletes both sessions under the account's auth lock.
6. The mobile device runs as a pod under Docker (off unless `EMULATOR__ENABLED`; needs a WSL kernel with binder, `docs/redroid.md`): a net-gateway container (`docker/net-gateway`, hev-socks5-tunnel, fail-closed nf_tables kill-switch, mapped DNS, IPv6 off; on its own bridge network with inter-container traffic off, adb only from the Docker gateway) and the redroid Android container in its network namespace (`--network container:`), so all of Android's traffic goes through the account's SOCKS5 proxy or nowhere, with no VPN or in-app proxy inside Android (HTTPS proxies are refused). The proxy reaches the gateway only as a file `docker cp`'d into it before each start, never env, argv, logs or errors; its host is resolved on the host. Android presents the mobile fingerprint's phone as a real build of it (`configs/oem_blueprints`, every `ro.product.*`/`ro.build.*`, its screen; serial and IMEI derived from the account id) with the proxy country's timezone and SIM carrier and the fingerprint's own language, through a block appended to the image's product `build.prop`, read last by init, before every cold boot (never the command line, which redroid re-splits on spaces) and runs the image of its SDK; every catalogue phone and SDK must have a blueprint build; it is started only once the gateway's tunnel is up. adb is published by the gateway on 127.0.0.1 at the first port + the pod's label index; the phone is shown in one scrcpy window per container. A running pod is never rebooted or reconfigured while its gateway runs the account's current proxy (compared by digest) and Android started after it, only signed in when its app shows intro or phone; one on another proxy is restarted, and a proxy change stops the pod. Device commands go through `adb shell` as argv lists; text is escaped or refused (a stored 2FA password it cannot type is refused before the number is sent); nothing is tapped that the UI dump did not show; sign-in state is read off the screen. A failed start undoes what it started; deleting the account removes both containers. A container's first boot, before the app starts, seeds the country's contacts and the phone's camera roll (EXIF from the blueprint's `camera`) once, behind a marker in `/data/local/tmp`; a failed seeding is logged and never fails the open.
7. Test both device shapes (desktop-first, mobile-first) and the refusal codes; i18n parity covers `DeviceRefusalCode`.
